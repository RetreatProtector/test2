Команда Что делает cd *название папки* - перейти в папку git init Инициализировать репозиторий git add . Добавить файлы для следующего коммита пишем либо точку - добавить все файлы, либо конкретный файл пиши git commit -m Зафиксировать изменения -m это ветка git push -u origin main Отправить коммиты в репозиторий git pull — это команда, которая стягивает изменения с удалённого репозитория (например, GitHub) и сразу применяет их к твоей текущей локальной ветке. git branch *название ветки* - создание новой ветки git checkout -- . - откат изменений (в случае с точкой всех файлов. если нужно конкрутного - указывай название) Из дипсика 1. Настройка (делается один раз) git config --global user.name "Имя" - Устанавливает имя автора коммитов git config --global user.email "mail@example.com" - Устанавливает email автора git config --list - Показывает все текущие настройки 2. Создание и клонирование репозитория git init Создаёт новый локальный репозиторий (папку .git) git clone Копирует удалённый репозиторий себе на компьютер 3. Основной рабочий цикл (99% времени) git status Показывает, какие файлы изменены, добавлены или удалены git add <файл> Добавляет файл в staging area (готовит к коммиту) git add . Добавляет все изменённые файлы git add -A Добавляет всё, включая удалённые файлы git commit -m "сообщение" Сохраняет изменения в истории с комментарием git commit -am "сообщение" Добавляет отслеживаемые файлы и сразу коммитит (для новых файлов не сработает) git push Отправляет коммиты на удалённый репозиторий git pull Стягивает изменения с удалённого репозитория и сливает с локальными 4. Работа с ветками git branch Показывает список локальных веток git branch -a Показывает все ветки (включая удалённые) git branch <имя> Создаёт новую ветку git checkout <ветка> Переключается на другую ветку git checkout -b <ветка> Создаёт новую ветку и сразу переключается на неё git switch <ветка> То же, что checkout, но современнее (только для переключения) git switch -c <ветка> Создать + переключиться (современный синтаксис) git merge <ветка> Сливает указанную ветку в текущую git branch -d <ветка> Удаляет локальную ветку (если она слита) git branch -D <ветка> Удаляет ветку принудительно git push origin --delete <ветка> Удаляет ветку на удалённом репозитории 5. Работа с удалёнными репозиториями git remote -v Показывает список удалённых репозиториев git remote add origin Привязывает удалённый репозиторий git remote remove origin Удаляет привязку к удалённому репозиторию git push -u origin main Первый пуш + запоминает связь (upstream) git push origin <ветка> Пушит конкретную ветку git pull origin <ветка> Тянет конкретную ветку git fetch Скачивает изменения, но не сливает их git branch --set-upstream-to=origin/<ветка> <ветка> Настраивает связь локальной ветки с удалённой 6. История и просмотр изменений git log Показывает историю коммитов git log --oneline То же, но кратко (по одной строке) git log --oneline --graph --all Красивое дерево всех веток git diff Показывает изменения, которые ещё не добавлены в staging git diff --staged Показывает изменения, которые уже в staging git show <коммит> Показывает содержимое конкретного коммита git blame <файл> Показывает, кто и когда менял каждую строку файла 7. Откат изменений (Осторожно!) git restore <файл> Отменяет изменения в файле (возвращает к последнему коммиту) git restore --staged <файл> Убирает файл из staging (но изменения остаются) git reset <файл> То же, что restore --staged git reset --soft HEAD~1 Отменяет последний коммит, но оставляет изменения в staging git reset --mixed HEAD~1 Отменяет коммит, изменения остаются в рабочей папке (по умолчанию) git reset --hard HEAD~1 Уничтожает последний коммит и все изменения (опасно!) git revert <коммит> Создаёт новый коммит, который отменяет указанный (безопасно) 8. Временное сохранение (Stash) git stash Временно прячет незакоммиченные изменения git stash list Показывает список спрятанного git stash pop Возвращает последние спрятанные изменения git stash apply Возвращает, но не удаляет из stash git stash drop Удаляет последний stash 9. Теги (Версии) git tag Показывает список тегов git tag v1.0.0 Создаёт тег на текущем коммите git push origin v1.0.0 Отправляет тег на GitHub git push origin --tags Отправляет все теги 10. Продвинутое (для DevOps) git cherry-pick <коммит> Переносит конкретный коммит из другой ветки git rebase <ветка> Перебазирует текущую ветку на другую (переписывает историю) git rebase -i HEAD~3 Интерактивный rebase последних 3 коммитов (можно squash, edit, drop) git bisect Бинарный поиск коммита, который сломал код git reflog Показывает всё, что ты делал в Git (спасает при потере коммитов) git submodule Работа с подмодулями (вложенные репозитории) Шпаргалка «Что делать, если...» Ситуация Команда Случайно удалил коммит git reflog → найти хеш → git reset --hard <хеш> Забыл добавить файл в последний коммит git add <файл> → git commit --amend Хочу изменить сообщение последнего коммита git commit --amend -m "новое сообщение" Закоммитил не в ту ветку git checkout правильная_ветка → git cherry-pick <хеш> Конфликт при merge Открыть файлы, убрать <<<<<<<,=======,> >>>>>>, затем git add и git commit Хочу посмотреть, что изменилось в конкретной строке git log -S "текст" Самый главный цикл (запомни наизусть) bash git status # посмотреть, что изменилось git add . # добавить все изменения git commit -m "..." # сохранить с комментарием git push # отправить на GitHub
